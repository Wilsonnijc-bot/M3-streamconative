# Construction concurrency and latency contract

Defaults: concurrent Deepgram/MAI, process-local HTTP connection pools, one embedding batch for all episodic and semantic texts generated by a clip, and two-segment graph-free decode/ASR lookahead in the benchmark. Memory generation, identity resolution, semantic integration and checkpoint commits remain chronological. No preparation worker accesses the memory graph.

| Scope | Recorded measurement | Interpretation |
| --- | --- | --- |
| ASR HTTP attempt | `asr_calls.jsonl`: request start/end, latency, provider, segment ID, retry, cache status, transport metrics | Each actual attempt, including failures; cache hits are explicit |
| Parallel ASR stage | `stage_details.voice.asr_total_ms` | Provider-group wall time; not the sum of provider times |
| Gemini call | `gemini_calls.jsonl`: request start/end, latency, tokens, segment/question/method, transport metrics | Includes actual request overhead; non-streaming TTFT remains unavailable |
| Text embedding batch | `stage_details.text_embedding_batch` | Whole-batch time, input count, tokens and each attempt; individual-text latency is unavailable |
| HTTP transport | `client_previously_used`, TCP connect and TLS handshake event counts, `http_wall_ms` | A reused client does not necessarily reuse a TCP connection |
| Preparation | `pipeline_timing.preparation_work_ms` | Decode and ASR work in the preparation worker |
| Consumer wait | `consumer_wait_ms` | Ordered consumer waiting for prepared data |
| Ready queue | `ready_to_ordered_ms` | Prepared data waiting until its chronological turn |
| Ordered processing | `ordered_processing_ms` in clip audit | Identity handling, Gemini, batch embeddings, graph integration and audit work |
| Segment through checkpoint | `segment_schedule_events.jsonl`: `segment_latency_ms` | Prefetch admission to persisted build-state checkpoint, including waits |
| Ordered stage through checkpoint | `ordered_stage_ms` | Prepared segment admission to the ordered stage through checkpoint completion |
| Throughput | Committed video duration / elapsed run wall time, grouped by execution policy | Report separately from per-segment latency; skip time is not counted as committed video |

Overlapping stages must not be summed as end-to-end latency. Prefetching may increase an individual segment's admission-to-commit time while improving throughput. Do not divide batch latency by the number of texts and call it individual-text latency.

`execution_policies.jsonl` records the first segment under the optimized policy. Earlier serial records remain unchanged. Do not pool old and new construction timings into one unlabeled comparison.

All A/B/C/D QA trials run after construction workers have exited. They use immutable, correctly timed snapshots and retain the controller/one-shot rules. Retrieval-stage timings remain separate from final-answer latency and offline preparation. No cross-question batching was added.

## Warm retrieval policy

All A/B/C/D evaluation rows use `latency_mode=warm_retrieval_uncached_question`. Before the timed trial, load the snapshot and issue one fixed neutral retrieval probe (`Describe a recent observed activity.`). Discard its evidence. This initializes retrieval backends, model kernels, indexes and relevant API connections; the actual benchmark question is never used as a warmup. Each actual question still begins with an empty retrieval context and fresh query embeddings, and B/C/D still make exactly one question retrieval request and one Gemini answer call.

`retrieval_warmup.jsonl` records every probe and its full stage timings, plus snapshot-load latency. These setup operations do not enter QA retrieval counts, QA Gemini counts, accuracy or warm latency aggregates. Any warmup failure remains visible and cannot be labeled a successful warm trial.

Timed Mandol results include `warm_engine=true`; initialization is separately excluded, while the tiny readiness check remains timed. The final validator rejects non-warm trial rows. Native StreamMeCo receives the same neutral-probe warmup treatment. Cloud-provider internal model residency cannot be controlled; actual network/API latency remains measured. Adapter conversion and index construction are still offline costs incurred when creating/updating memory, not on every query against an unchanged loaded index.

The original preflight review remains a cold-start record. It is not retroactively relabeled or corrected by subtracting initialization time.
